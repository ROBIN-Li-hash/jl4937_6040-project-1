# 数据清洗策略说明

配套代码：`data_cleaning_strategy.ipynb`。以下数值来自原始 CSV 全量检查，未去重。

## 数据概况

- 8,495,421 行，11 列；非缺失 AnimalId 有 9,087 个。
- 日期：2019-06-14 至 2021-10-24。
- AnimalId、LactationNumber、ReproductionStatus 同时缺失 1,701,003 行（20.0226%）；DaysInMilk 另有 4 行缺失。
- Avgmilkflow 缺失 172 行，为零 215 行；Flow30_60Session 为零 3,155 行。
- 完整重复的额外行数为 60,653。原 notebook 已执行过完整去重，剩余 8,434,768 行。
- 前两分钟产奶量超过整次产奶量的记录有 3,392 行。
- 原始数据按 AnimalId、LactationNumber、EventDate、milking 检查完整键，重复额外行数为 226,083。这包含完整重复，不能与完整重复数量直接相加。

## 处理顺序与依据

1. **先保护字段含义。** AnimalId 是标识，读取时指定 string；负号不意味着错误。已转浮点的长整数可能损失精度，必须重新读取原文件。日期转 datetime；milking 作为类别处理。
2. **核查重复。** 全字段重复先标记，确认重复导出后去重。候选事件键发生冲突时，核实是否存在重复挤奶、补录或缺少牧场/设备/时间戳字段；不要擅自取均值或只留第一条。
3. **区分缺失原因。** 四个牛只背景字段整块缺失，值得核查原始关联或导出过程，但不能仅凭这个模式断定原因。保留这些记录做事件层面的描述统计；牛只纵向分析另建有身份信息的子集。不能填补 AnimalId，也不能把所有未知牛只当作同一只牛。
4. **处理明确的逻辑冲突。** 前两分钟产量高于整次产量，在相同单位、相同事件、累计量定义下不一致。先核查单位和字段定义，再决定修正哪个字段、设为缺失或排除。平均流速为零但产量为正应复核；短时段流速为零不一定错误。
5. **审核极端值。** DaysInMilk 最大 870、LactationNumber 最大 12、Avgmilkflow 最大约 23.50。不能仅因偏离常见范围就删除。结合牛只、胎次、日期、班次和其他测量检查，比较保留与排除可疑值时的结果。
6. **核查纵向一致性。** 同一牛只同一胎次内，日期减去泌乳天数应大致稳定；检查跨度异常的分组，避免跨胎次插值或填充繁殖状态。
7. **按目的预处理。** 描述统计无需标准化或补齐全部缺失；线性模型可标准化连续变量，类别变量编码。模型插补、标准化等仅在训练集拟合。

## 建模时特别注意

预测新牛只时按 AnimalId 分组切分；预测未来时按时间切分。随机按行切分可能使同一牛只的相邻记录同时进入训练和测试。

若在挤奶前预测 YieldSession，本次平均奶流速、整次时长、前两分钟产量和本次 30–60 秒流速当时均不可得。尤其平均流速与产量/时长非常接近：比值中位数约 0.987；使用它们可能使预测效果被高估。

notebook 默认只标记和输出审计文件，不自动插补或缩尾。确认重复导出后可开启 DROP_EXACT_DUPLICATES；完整副本导出与建模示例也各有开关。
